## [utils.py](../notebooks/utils.py)

This is a python script file colleting helper functions for the following notebooks.

In this file the project root, the splits, and the default image size are defined.

It includes a helper function to search for the path of an image file and its corresponding lableing txt file with just the "name" of the image.

It also includes the more important function `build_group_boxes` which takes a dataframe of an image (meaning the bounding boxes of the different animals) and then uses DBSCAN to cluster them togehter. It returns a dataframe of the different clusters (their group composition, animal count, box coordinates,...).

We went with DBSCAN as it allows for a dynamic amount of Animals inside of a group, but not with HDBSCAN as we wish to manually define how dense (close) animals should be for a group (HDBSCAN would often choose the entire image).
The group box coordinates are determined by the the images most to the left, right, bottom and top as well as a certain amount of padding or minimum size if the cluster was deemed to small.

## [match_lables_with_gt.ipynb](../notebooks/match_lables_with_gt.ipynb)

This is the first notebook to execute if both the ground truth (GT) data as well as the RGB data are present and in the correct folder structure.

It will generate 4 CSVs (the 3 splits and one for all). The CSVs hold the information of each bounding box (from the lables txt) matched with the species and the encoded species id. The bounding boxes here are already converted from yolo to image coordinates.

To match the GT boxes with the unlabled cleaned boxes we calculat the distance of both boxes centeres to each other as well as the iou (overlapping area). This is done for every combination of GT and cleaned box. Then the cleaned boxes are matched to the best box by distance.

Finally after the classes are assigned to each cleaned box (and the ones where no class could be found are filled with the next best class of the image) the image class is converted to our mapping, there are 72 ids in the GT mapping, but far fewer species as we only care about species we encode these ids into our format, (manually created and stored as a json), where each species is assignd a letter.

## [view_images.ipynb](../notebooks/view_images.ipynb)

This is a notebook that allows one to look at different frames utilising code from the utils.py and the csv from the previous notebook.

It shows the image as well as the cleaned bounding boxes, the class of each bounding box, the bounding box of the cluster and the amount of animals of each class in this cluster.

## [cut_images.ipynb](../notebooks/cut_images.ipynb)

This notebook utilies functions from the `utils.py` as well as the CSVs generated by the `match_lables_with_gt.ipynb`.

It is a simple notebook that iteratoes over all possible clusterd boxes and cuts them out of the original image, then saves them with an encoded name of format "{flight_id}_{frame_id}_g{cluster_id}_{species_suffix}.jpg", where the species suffix is a encoding of the amount of species in this cluster, e.g. 2b would be 2 deer, as each species class has ony 1 letter decoding it is no challenge.
